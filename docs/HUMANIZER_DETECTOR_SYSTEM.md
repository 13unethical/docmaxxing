# Единая система: humanizer + детектор

Один документ, по которому развиваются и humanizer, и детектор. Стратегию меняем только если
изменение прошло проверку на «золотом наборе» в Turnitin (шаг 5). Всё остальное — гипотезы.

## 0. Главный принцип

**Единственный судья — Turnitin.** Наш детектор — дешёвая копия Turnitin для отбора вариантов,
не цель. Каждая проверка в Turnitin превращается в разметку и идёт в обучение обеих моделей.

```
 источники (ChatGPT / Claude / Gemini)
        │
        ▼
 humanizer ──► текст ──► Turnitin (слоты) ──► разметка по предложениям
    ▲                                              │
    │  SFT + DPO на оценках Turnitin                │  обучение детектора
    └──────────────────────────────────────────────┴──► детектор (отбор вариантов)
```

Что подтвердили 3 ноября 2026: детектор поставил 0% двум текстам, у которых в Turnitin 48% и 49%
(пропустил 12 из 26 помеченных абзацев). Значит, режим, который полагается только на наш детектор,
нельзя выпускать без проверки в Turnitin.

## 1. Как работают Turnitin и топ-humanizer'ы

### Turnitin

- Трансформер-классификатор, а не perplexity/burstiness. Документ режется на окна по 5–10
  предложений («несколько сотен слов»), окна сдвигаются по одному предложению. Оценка
  предложения — взвешенное среднее окон, в которые оно попало; порог предложения ~0.8–1.
  Документ получает видимый % только если помечено >20% предложений (1–19% показываются как `*%`).
  Минимум 300 слов. Списки, таблицы, литература не оцениваются.
  [Архитектура и протокол тестирования (PDF)](https://www.buffalo.edu/content/www/lms/guides-instructors/integrations/turnitin/_jcr_content/root/maincontent/par/download/file.res/Turnitin%E2%80%99s%20AI%20Writing%20Detection%20Model%20Architecture%20and%20Testing%20Protocol.pdf),
  [блог Turnitin](https://www.turnitin.com/blog/ai-writing-detection-what-academic-leaders-need-to-know-as-technology-matures)
- С августа 2025 отдельно ловит «AI-текст, переписанный bypasser/humanizer-инструментом»;
  модель обновляется (последнее — октябрь 2026), старые отчёты не пересчитываются.
  [Журнал изменений модели](https://guides.turnitin.com/hc/en-us/articles/28294949544717-AI-writing-detection-model)
- Вывод для нас: «поверхностный» парафраз (синонимы, порядок слов) Turnitin видит. Работает только
  переписывание, которое меняет распределение слов так, как пишет человек, — и проверять это можно
  только в самом Turnitin.

### StealthWriter

- Модели Ghost 5.2 Mini / Pro (май 2026), уровни 1–10: 1–3 почти не меняют текст, 7–10 переписывают
  агрессивно. Встроенный детектор и альтернативы по каждому предложению.
  [Сайт](https://stealthwriter.ai/), [changelog](https://stealthwriter.ai/changelog),
  [обзор с тестами](https://fast.io/resources/stealthwriter-ai-review-2026/)
- По независимым обзорам: на GPTZero/ZeroGPT работает, на Turnitin нестабильно, высокие уровни
  иногда искажают смысл. [Обзор](https://www.naturalrewrite.com/blog/stealthwriter-review)

### Как устроены сильные humanizer'ы (исследования)

- **Парафраз-модель** (DIPPER, 11B): переписывает абзац с учётом контекста, управляет силой замен.
  Обходит GPTZero/DetectGPT, сохраняя смысл.
  [Статья](https://arxiv.org/abs/2303.13408), [код](https://github.com/martiansideofthemoon/ai-detection-paraphrases)
- **Парафраз под управлением детектора** (Adversarial Paraphrasing, NeurIPS 2025): LLM переписывает,
  а детектор выбирает продолжения с наименьшей AI-оценкой. Переносится на другие детекторы, если
  детектор-проводник хороший. Это то, что делает наш «лучший из 8»; слабое место — качество
  нашего детектора. [Статья](https://arxiv.org/abs/2506.07001), [код](https://github.com/chengez/Adversarial-Paraphrasing)
- **Дообучение на предпочтениях** (DPO): модель учится на парах «хороший / плохой вариант» одного
  абзаца. У нас пары берутся из Turnitin: непомеченный вариант против помеченного.
  [TRL DPOTrainer](https://huggingface.co/docs/trl/dpo_trainer), [статья DPO](https://arxiv.org/abs/2305.18290)
- Бенчмарк устойчивости детекторов (атаки, декодирование, новые модели):
  [RAID](https://github.com/liamdugan/raid), [статья](https://arxiv.org/abs/2405.07940).
  Zero-shot детектор как второй сигнал: [Binoculars](https://github.com/ahans30/Binoculars).

## 2. Данные — один формат, одно хранилище

| Набор | Откуда | Где лежит | Для чего |
|---|---|---|---|
| Источники (AI-тексты) | ChatGPT / Claude / Gemini по студенческим заданиям | `data/humanizer_training/source_pool`, `data/detector_corpus/chatgpt.jsonl` | вход humanizer'а, AI-класс детектора |
| Учитель | StealthWriter уровень 10 на этих источниках | `data/humanizer_training/bulk/` | SFT humanizer'а |
| Разметка Turnitin | наши отправки + отчёты клиентов (согласие `yes_all`) | volume `tt-detector`: `labels_vps.jsonl`, `batch_*.jsonl` | обучение детектора, DPO |
| Человеческие тексты | эссе, arXiv, Wikipedia и др. | volume `tt-detector`: `ext.jsonl`, `extra_*.jsonl` | контроль ложных срабатываний |

Правила: клиентские тексты не покидают сервер/GPU; каждая отправка в Turnitin сохраняется с
`doc`, `sid`, вариантом и итогом; `*%`-документы без «Get AI» в разметку не идут.

## 3. Детектор — копия Turnitin

1. **Окна как у Turnitin.** Сейчас у нас окна по 110 слов и порог 0.5; у Turnitin — 5–10 предложений
   и порог ~0.8–1. Перейти на окна по 5–8 предложений со сдвигом в одно предложение и подобрать порог
   так, чтобы наш % документа совпадал с Turnitin на размеченных отчётах. Код: `services/ai_detector.py`,
   обучение `ai_detector/train_modal.py`.
2. **Главная метрика — полнота на переписанных текстах**: доля абзацев, помеченных Turnitin, которые
   помечаем и мы (сейчас на тесте 3 ноября — 0 из 12). Плюс: корреляция % документа с Turnitin,
   ложные срабатывания на человеческих текстах ≤ 3%.
3. **Переобучение** раз в неделю (`retrain`, понедельник 03:00 по Ташкенту) на всех метках; выпуск —
   по среднему 3 прогонов с разными сидами (уже так).
4. После каждого выпуска проверять, что сервис отдаёт новые веса (а не только новое имя версии).

## 4. Humanizer — учится у Turnitin

1. **SFT** (есть): Qwen3-8B + LoRA на парах «источник → текст учителя». Фильтр: в обучение только
   пары, где текст учителя прошёл Turnitin или наш детектор с хорошей полнотой.
   Код: `humanizer_student/train_modal.py` (`score` → `prepare` → `train`), сборка данных
   `build_section_sft` на сервере.
2. **DPO** (следующий шаг): для каждого документа 3–4 разных переписывания → Turnitin → для каждого
   абзаца пара «непомеченный (chosen) / помеченный (rejected)». 20 документов × 4 варианта = 80 слотов
   ≈ 150–250 пар. Обучение через TRL `DPOTrainer` поверх текущей LoRA, `beta` 0.1.
3. **Вывод на сайте**: отбор лучшего варианта нашим детектором («лучший из 8») — только пока детектор
   проходит пункт 3.2. Режим «1 вариант + переписать помеченное» (`HUMANIZER_STUDENT_PICK=document`)
   включать, только когда детектор ловит абзацы, помеченные Turnitin.

## 5. Золотой набор и правило выпуска

- Слот стоит $3, поэтому набор маленький. **v1 (сейчас): 8 документов** из test-части обучения
  (4 Claude, 4 Gemini, ~1200 слов исходника, `tmp/golden_v1.py`). Для них уже есть выход
  StealthWriter уровня 10, так что планка бесплатна. ChatGPT добавим, когда bulk StealthWriter
  соберёт GPT-источники (раздел 8, шаг 6).
- Каждый кандидат (новая модель humanizer'а, новый режим, новый детектор для отбора) прогоняется
  на всём наборе → Turnitin (8 слотов = $24, `tmp/golden_v1_submit.py`).
- Метрики: средний AI%, доля 0%, доля ниже 20% (`0%` или `*%`), смысл сохранён (сходство по
  эмбеддингам ≥ 0.85, все числа и ссылки на месте).
- **Выпускаем, только если кандидат лучше текущего на сайте по доле ниже 20% и не хуже по среднему
  AI%.** Решение и цифры записываем в журнал решений (раздел 7).

## 8. Пошагово: добавить ChatGPT в обучение

Код уже есть: `services/openai_client.py`, `services/humanizer_training/chatgpt_corpus.py`,
`scripts/gen_chatgpt_corpus.py`. Нужен только ключ.

1. **Ключ OpenAI.** Создать на [platform.openai.com/api-keys](https://platform.openai.com/api-keys),
   поставить лимит расходов в [Limits](https://platform.openai.com/settings/organization/limits)
   (например $50). Цены: [openai.com/api/pricing](https://openai.com/api/pricing/).
2. **Прописать ключ** в `.env` локально и на сервере: `OPENAI_API_KEY=...` (в чат не вставлять).
3. **Пробный запуск, 5 текстов:**
   ```bash
   python3 scripts/gen_chatgpt_corpus.py --count 5 --budget-usd 1
   ```
   Проверить `data/detector_corpus/chatgpt.jsonl`: студенческий стиль, без Markdown, 300–900 слов.
4. **Корпус для детектора, ~1500 текстов** (≈$30; повторный запуск продолжает, а не дублирует):
   ```bash
   python3 scripts/gen_chatgpt_corpus.py --count 1500 --budget-usd 30
   python3 scripts/gen_chatgpt_corpus.py --export-detector data/detector_corpus/chatgpt_v1.jsonl
   ```
   Смесь моделей по умолчанию: `gpt-4o:3,gpt-5:2,gpt-4.1:2,gpt-5-mini:2,gpt-4o-mini:1` (`--models`).
5. **Загрузить в детектор и переобучить:**
   ```bash
   tmp/modal-venv/bin/modal volume put tt-detector data/detector_corpus/chatgpt_v1.jsonl /chatgpt_v1.jsonl
   tmp/modal-venv/bin/modal run ai_detector/train_modal.py::retrain
   ```
   Проверка выпуска следит, чтобы полнота на ChatGPT (`chatgpt_recall`) не упала.
6. **ChatGPT как источник для humanizer'а** (на сервере, после деплоя кода):
   ```
   HUMANIZER_SOURCE_MIX=openai:gpt-4o:3,openai:gpt-5:2,openai:gpt-4.1:2,openai:gpt-5-mini:2
   HUMANIZER_TRAINING_BULK_SOURCE_PROVIDERS=openai
   HUMANIZER_TRAINING_BULK_LEVELS=10:1
   ```
   Пул наполнится GPT-текстами (~300 документов), bulk прогонит их через StealthWriter уровня 10,
   дальше — `build_section_sft` → `humanizer_student/train_modal.py` (`score` → `prepare` → `train`)
   → новая версия humanizer'а → золотой набор (раздел 5) → выпуск или отказ.
